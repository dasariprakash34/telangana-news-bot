## Design
- src/tgnews/storage_github.py: GithubImageStore(token, repo, branch, public_base, *, http, sleep, clock, unique, pause),
  .upload(paths, prefix), .prune(days, now, max_files=60), keep_days(env), check_public_url(url).
- storage.py: S3 code untouched; added build_uploader(env) -> callable(paths, prefix) (same signature the pipeline uses).
  STORAGE_PROVIDER github (default, also when empty) | s3. pipeline.py unchanged.
- cli.py: build_deps uses build_uploader; new commands prune-images and check-images are handled before build_deps
  (no DB/LLM/IG needed); errors scrubbed, Telegram alert on failure. prune-images is a no-op for s3.
- Paths: posts/YYYYMMDD/<sanitised prefix>-<random 6 hex>-<n>.jpg. The random part is added so that a retried story
  (claim released after an infra failure) does not hit a path that a partially failed earlier attempt created.
  Only 201 counts as success; 409/422 -> "not overwriting" error; 200 (would mean an update) -> error.
- Rate pacing: 1 s sleep between files (injectable), also between deletes.
- Token: never in errors/repr/str/logs; httpx/httpcore loggers at WARNING; GitHub response bodies never echoed; `from None`.
- Prune: lists posts/, strict 8-digit + valid-date dirs older than cutoff (date < today - N days), oldest first, DELETE with
  sha, max 60 per run, 404 tolerated; nothing outside posts/.

## Unverified / concerns
- Instagram accepting raw.githubusercontent.com or jsDelivr URLs is UNVERIFIED (raw serves text/plain-ish headers
  historically unknown for images; nosniff etc.). check-images only proves public fetchability, not Instagram acceptance.
- Real GitHub API behaviour (201/422 codes, DELETE body, directory listing limit of 1000 files) tested only against a fake.
- Repo growth: git history keeps deleted blobs; pruning keeps the working tree small but repo size (1 GB soft guidance) grows.
- Fine-grained PAT expiry will break uploads silently until the Telegram alert (StorageError) fires.
- IMAGES_KEEP_DAYS minimum is 1 in code; README advises not below 3.
- Partial uploads leave orphan files (pruned later).
- Workflow uses vars.STORAGE_PROVIDER; unset var = empty string = github.
